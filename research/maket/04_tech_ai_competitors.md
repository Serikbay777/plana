## 0. Что такое Maket.ai (вводно)

Maket — облачный генеративный AI-инструмент для архитектурного проектирования на ранних стадиях (концепт, fit-test, feasibility). Основной упор сделан на **резидентскую жилую типологию** (single-family, small multifamily, townhouses, ADU), а не на крупные коммерческие объекты. Ключевая ценность — превратить параметры участка и зонирование в десятки вариантов планировок и фасадов за минуты, без CAD-навыков.

Целевые сценарии:
- Архитекторы — быстрый feasibility и презентации клиенту.
- Девелоперы / home builders — массовый перебор массингов под зонирование.
- Real estate / лендлорды — оценка потенциала участка.
- DIY homeowners — пристройка / реконструкция без архитектора.

## 1. Технологический стек

### 1.1. ML/AI-модели
Публично Maket не раскрывает архитектуру нейросетей в деталях, но по фичам и косвенным признакам (демо, блог, выступления CEO) стек выглядит так:

| Компонент | Технология (вероятная) |
|---|---|
| Генерация планов (floor plan layouts) | Гибрид: **constraint solver + graph-based generative model**, по структуре близкий к House-GAN / House-GAN++ / Graph2Plan. Не чистый pixel-diffusion. |
| Стилизация / рендеры фасадов | **Diffusion-модель** (вероятно дообученный Stable Diffusion с ControlNet по линиям/depth) — стандарт индустрии 2023–2025. |
| Текстовые подсказки / чат-ассистент по building codes | **LLM** (через API OpenAI / Anthropic), с RAG поверх корпуса нормативов. |
| Cost estimation | Не ML, а **rules-based** + справочники цен (RSMeans-подобные). |
| Code compliance | **Rules-based engine** с табличными правилами зонирования (setbacks, FAR, height, lot coverage). |

> Diffusion применяется именно для **рендеринга/визуализации**, а не для генерации планов. Сами планы — это векторная задача (комнаты, стены, двери), которую диффузия решает плохо. Это важное архитектурное решение Maket.

### 1.2. Облачная инфраструктура
- **Хостинг:** `[требует верификации]` — судя по типичному стеку канадских AI-стартапов и интеграциям, наиболее вероятна связка **AWS** (us-east-1) + GPU-инференс на **AWS SageMaker / EC2 g5** или **Replicate / Modal** для diffusion-нагрузок.
- **CDN:** Cloudflare (по DNS-признакам обычно).
- **Auth:** Auth0 / Firebase Auth `[требует верификации]`.

### 1.3. Web-stack (frontend)
По косвенным признакам (UX веб-приложения, SPA-поведение, маркетинговый сайт):
- **Маркетинг:** Webflow или Next.js (статика).
- **Приложение (app.maket.ai):** SPA на **React** (вероятно Next.js 13+), state — Redux/Zustand.
- **Canvas-рендер планов:** скорее **Konva.js / Fabric.js** или собственный 2D-canvas (план — это плоская графика, three.js здесь избыточен). Для 3D-превью массингов — **three.js / react-three-fiber**.
- **Геометрия:** библиотеки типа `flatten-js`, `martinez-polygon-clipping` для булевых операций над контурами.

## 2. AI Capabilities — детально

### 2.1. Floor plan generation
- **Input:** контур участка (загружается из shape-файла, или рисуется руками, или подтягивается из cadastre/Google Maps), параметры программы (кол-во спален, ванных, этажей), стиль.
- **Output:** N вариантов планировки (обычно 5–30), с расстановкой стен, дверей, окон, лестниц.
- **Алгоритм:** граф комнат → планировочная схема → векторизация. Учитываются adjacency constraints (кухня рядом со столовой и т.п.) и code constraints (минимальные площади, ширины коридоров).
- **Latency:** `[требует верификации]` обычно 20–90 секунд на пакет вариантов.

### 2.2. Style transfer / рендеры
- Из плана генерируется 3D-массинг → depth/normal maps → diffusion-рендер фасада в выбранном стиле (modern, farmhouse, craftsman и т.д.).
- Latency на рендер: 10–30 сек на изображение.

### 2.3. Cost estimation
- Rules-based: квадратные футы × региональный $/sqft с разбивкой по конструктиву (foundation, framing, MEP, finishes).
- Не ML-модель, а калькулятор поверх таблиц.

### 2.4. Code compliance / Zoning AI Assistant
- Это **главная маркетинговая фича Maket** последние 1.5 года.
- Под капотом: **LLM + RAG** по корпусу муниципальных zoning bylaws. Пользователь спрашивает «what's the max FAR on my lot in Toronto R2», LLM находит релевантный пункт и цитирует.
- Хард-правила (setbacks, FAR) применяются к самой генерации плана как ограничения солвера.

### 2.5. Latency сводно
| Операция | Время |
|---|---|
| Генерация набора планов | ~30–90 сек |
| 3D-массинг | мгновенно |
| Diffusion-рендер | 10–30 сек |
| Ответ Zoning Assistant | 3–10 сек |

## 3. API и интеграции

> Это самая «слабая» зона Maket по сравнению с конкурентами (TestFit, Hypar).

| Возможность | Статус `[требует верификации актуального состояния]` |
|---|---|
| Публичный REST API | **Нет** публичного на момент знаний (январь 2026). Возможен enterprise-доступ под NDA. |
| Webhooks | Не заявлены. |
| Плагин Revit | **Нет**. |
| Плагин Rhino / Grasshopper | **Нет** (в отличие от Hypar/Finch). |
| Плагин AutoCAD | **Нет**. |
| Плагин SketchUp | **Нет**. |
| Export DWG | **Да** — основной экспортный формат. |
| Export PDF | Да. |
| Export PNG / JPG | Да. |
| Export IFC (BIM) | **Ограниченно / нет** — Maket позиционируется как pre-BIM инструмент, выгрузка идёт в DWG, дальше пользователь сам открывает в Revit. |
| Export SKP / 3DM | `[требует верификации]`, как правило нет. |
| Zapier / Make | Нет нативной интеграции. |

**Вывод:** Maket намеренно остаётся **standalone-приложением для концепт-стадии**, а не звеном BIM-конвейера. Это сознательная стратегия — не конкурировать с Revit, а отдавать ему DWG-файл.

## 4. Данные

### 4.1. Building codes / Zoning regulations
- **География покрытия `[требует верификации]`:** изначально Канада (Ontario, BC, Quebec — родина основателей), далее США (по городам — NYC, LA, Toronto, Vancouver и т.п.). Покрытие неравномерное и постепенно расширяется на основные метрополии.
- **Источник:** парсинг муниципальных bylaws + ручная курация командой. Не существует «единой базы» — каждый город заводится отдельно.
- **Модель монетизации данных:** часть городов в базовом тарифе, для остальных — enterprise / custom.

### 4.2. Catalog материалов для cost estimation
- Региональные справочники $/sqft, не пользовательский catalog материалов.
- В отличие от TestFit/Hypar, Maket не позволяет глубоко настраивать свою цену за SKU.

### 4.3. Кастомные templates / семейства
- Можно сохранять «свои стили» и предпочтения программы.
- Загрузка собственных Revit-семейств / Rhino-блоков — **нет**.

## 8. Use cases по индустриям

1. **Архитектурные бюро (малые/средние).** Использование на пресейле — за час показать клиенту 5 вариантов под его участок. Дальше — экспорт DWG и продолжение в Revit/ArchiCAD.
2. **Девелоперы single-family / townhouse.** Перебор вариантов под зонирование пачкой лотов; быстрая оценка GFA/yield.
3. **Home builders / production builders.** Адаптация типового каталога планов под конкретный участок и локальный zoning.
4. **Real estate / brokers.** Маркетинговый материал «что можно построить на этом участке» для листингов земли.
5. **DIY homeowners.** Пристройка, гараж, ADU/laneway house — концепт для разговора с подрядчиком или муниципалитетом.
6. **Land assemblers / investors.** Feasibility-скрининг участков до покупки.
7. **Муниципалитеты / urban planning** (нишево) — sandbox для проверки последствий изменения bylaws.

## 9. Резюме для продукта/инвестпринятия

**Сильные стороны Maket:**
- Уникальный gap в рынке: «AI для малой жилой», где TestFit/Hypar не играют.
- Zoning AI chat — реальный moat, требующий ручной курации данных, не воспроизводится за выходные.
- Low-touch UX, расширяющий рынок на не-архитекторов.

**Слабые стороны / риски:**
- Нет нативных плагинов и API → пользователь упирается в потолок при попытке перейти в production-документацию.
- Зависимость от ручной курации zoning-базы → масштабирование на новые юрисдикции дорогое.
- Конкуренция «сверху» (Autodesk Forma) и «снизу» (общие LLM-агенты типа ChatGPT с плагинами CAD).
- Diffusion-рендеры — commodity-фича, легко повторяемая.

**Где Maket может реально победить:** в нише «AI-копайлот для девелоперов SFH/ADU в Северной Америке», если успеют закрыть BIM-мост и API раньше, чем Autodesk Forma спустится на residential.
