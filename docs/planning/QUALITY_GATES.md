# Quality Gates

## Общий принцип

Функция не считается готовой, если она только выглядит рабочей. Для каждого
типа функции требуется проверяемое доказательство.

## Definition of Ready

Story готова к реализации, если:

- понятна пользовательская проблема;
- указано, что входит и не входит;
- определены acceptance criteria;
- известен источник данных;
- понятны состояния ошибок;
- определены тесты;
- story помещается в одну сфокусированную итерацию;
- нет зависимости от неутверждённого продуктового решения.

## Definition of Done

Story завершена, если:

- acceptance criteria выполнены;
- код соответствует архитектурным принципам;
- тесты добавлены и проходят;
- нет новых lint, typecheck или security ошибок;
- документация обновлена при изменении поведения;
- UI проверен в браузере, если он менялся;
- ошибки и ограничения видимы пользователю;
- изменения можно безопасно откатить.

## Gates по типам функций

### Backend API

- схема запроса и ответа;
- validation ошибок;
- auth и ownership;
- unit или integration test;
- структурированный лог;
- timeout и лимиты для тяжёлых операций.

### Frontend

- loading, empty, error и success states;
- browser verification;
- отсутствие скрытых demo-действий;
- доступность основных контролов;
- сохранение состояния или явное предупреждение о несохранённых изменениях.
- сохранение прогресса и результатов при переключении секций;
- отсутствие видимых доступных кнопок без работающего действия;

### AI

- eval-набор;
- измерение latency и стоимости;
- schema validation;
- безопасная обработка отказа провайдера;
- отсутствие прямого повреждения сохранённой модели.

### CAD, PDF и IFC

- единицы измерения;
- правила слоёв или свойств;
- golden file;
- round-trip или открытие в целевом инструменте;
- экспорт текущей версии проекта;
- явное сообщение о потерянных данных.

### Validators

- источник и версия нормы;
- положительный и отрицательный тест;
- объяснение входных значений;
- геометрия нарушения, если применимо;
- `not_checked`, если данных недостаточно.

### Cost

- источник ставок;
- дата и регион;
- диапазон точности;
- формула;
- предупреждение, что это не смета, если расчёт укрупнённый.

## Обязательные команды CI

Целевой минимальный набор:

```bash
npm run lint
npm run build
python -m pytest tests -q
python -m ruff check plana_engine tests
python -m mypy plana_engine
```

CI не должен собирать ручные скрипты как pytest-тесты.

## Ralph guardrails

Ralph можно запускать, если:

- рабочее дерево чистое;
- используется отдельная ветка;
- базовые проверки зелёные;
- одна story не требует архитектурного решения;
- acceptance criteria проверяемы;
- story не содержит формулировок вроде "сделать весь редактор".
