# AI Strategy

## Цель

AI должен сокращать время от намерения пользователя до проверяемого варианта,
не скрывая ограничения и не подменяя детерминированную геометрию.

## Целевой pipeline

```text
User brief
  -> structured requirements
  -> user confirmation
  -> constraints
  -> deterministic generator or solver
  -> candidate layouts
  -> validators
  -> scoring
  -> ranked variants
  -> explanations
```

## Разрешённые AI-задачи

- извлечение параметров из brief;
- классификация неоднозначных входных данных;
- объяснение отличий вариантов;
- формирование безопасных edit operations;
- генерация пользовательских подсказок;
- суммаризация результатов проверок.

## Задачи обычного кода

- создание и изменение геометрии;
- проверка пересечений и связности;
- расчёт площадей;
- нормативные проверки;
- scoring вариантов;
- импорт и экспорт;
- контроль заблокированных элементов;
- хранение и версионирование.

## Interactive edit

AI-редактор должен возвращать ограниченный набор операций, например:

```json
[
  {
    "op": "move_room",
    "room_id": "room-12",
    "dx": 0.5,
    "dy": 0.0
  }
]
```

Перед применением операции проходят:

1. проверку схемы;
2. проверку прав и locks;
3. геометрическую проверку;
4. пересчёт метрик;
5. validators;
6. подтверждение пользователем для значимых изменений.

## Evals

AI-функция не считается готовой без набора eval-кейсов.

Минимальные eval-наборы:

- brief parsing на реальных формулировках;
- корректность обязательных полей;
- устойчивость к противоречивым требованиям;
- edit instructions;
- отказ от неподдерживаемых действий;
- стоимость и latency;
- отсутствие изменения заблокированных элементов.

## Ограничения и стоимость

- модель и параметры выбираются по задаче, а не единообразно для всех запросов;
- каждый AI endpoint имеет timeout, лимит размера и rate limit;
- сохраняются provider, model, latency, token usage и оценочная стоимость;
- чувствительные данные не отправляются провайдеру без необходимости;
- ошибки AI не должны повреждать сохранённый проект.

## Не делать

- не использовать AI-визуализацию как доказательство корректности планировки;
- не просить LLM генерировать полный `LayoutFloor` без ограничений;
- не показывать AI-вывод как нормативное заключение;
- не строить сложный prompt до появления eval-набора.
