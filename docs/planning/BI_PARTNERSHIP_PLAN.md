# BI Group — план направлений и запрос данных

Рабочий документ для совместной группы Plana ↔ BI-Product. Готовится к
следующей итерации после звонка 18.06.2026.

Источник: [`docs/Заметка_BI-Product_2026-06-18.md`](../Заметка_BI-Product_2026-06-18.md).

Назначение по договорённостям звонка (шаги 5-6): обе стороны рисуют общий план
направлений (кластеры задач) → выбирают 2 задачи на 2 недели → BI выделяет
архитектора и данные.

> Состояния функций используются те же, что в [README](README.md): **Now** —
> доказано кодом и сценарием; **Next** — утверждено для ближайшей фазы;
> **Later** — направление, не обещание; **Not verified** — функция есть, но
> корректность не доказана.

---

## 1. Контекст и критический путь

Встреча была ознакомительной, не продажей. BI-Product — куратор интеграции
Plana в холдинг.

**Критический блокер — не технический.** Не определён статус Plana внутри
холдинга (произошёл ли M&A). Пока не ясен:

- BI не может передавать документы (всё под NDA);
- нет эталонных секций, обучающих данных, доступа к ЕГКН/ГИС-Саулет по договору BI;
- непонятны бюджет и форма договора.

**Эскалация:** Yeldos / Дмитрий ↔ Махамбетов Дамиржан.

Следствие для нас: в этой итерации мы двигаем только то, что докручивается
**в вакууме, без данных BI**, и готовим механизмы под будущие реальные данные,
а не выдумываем цифры.

## 2. Сдвиг приоритета (зафиксировать письменно)

Звонок показал: **приоритет BI №1 — не квартирография, а «визуализация ТЗ +
экономика в реал-тайм»** (Дмитрий, приоритизация «от меньшего к большему»).

Это разворачивает наш прежний порядок (посадка → квартирография → экономика).
Для BI «образ результата + смета» важнее точной квартирографии на старте.

Линию Maxat держим: **сначала фундамент 2D + СНиП + размеры + Revit-связка**,
3D/Unreal и мастер-планы — позже, изолированным экспортом.

## 3. План направлений (кластеры задач)

Кластеры пронумерованы по приоритизации BI. В каждом — что уже есть в коде и

### Кластер B1 — Визуализация ТЗ + экономика (приоритет BI №1)

**B1.1 Визуализация «образа результата» по параметрам**

| | |
|---|---|
| Статус | **Now** (с оговорками) |
| Что есть | 5 AI-вариантов типового этажа (`/visualize/floor-variants`), посадка-картинки, рендеры, PDF-альбомы |
| Разрыв | Нет ранжирования/подсказок вариантов на базе ТЗ/инсоляции |

**B1.2 Экономика в реал-тайм (параметр/материал/класс → стоимость)**

| | |
|---|---|
| Статус | **Not verified** (каркас готов, данные — заглушки) |
| Что есть | `cost/aggregate_cost.py`: GFA×ставка×класс×регион, пересчёт на лету (`/cost/aggregate`, `CostPlacementTab`); QTO из IFC (`cost/qto.py`) |
| Разрыв | Ставки — placeholder (`official=False`); нет явной причинности «материал/дизайн-код → дельта стоимости» в UI; нет реальной БД себестоимости |
| Зависит от BI | БД себестоимости элементов и формулы (после NDA) |

Подход к экономике совпадает с требованием Олеси/Maxat: детерминированный код
(модели данных, SQL/формулы), AI только ускоряет — не «чистый AI».

## 4. Предложение: 2 фокус-задачи на 2 недели

Выбраны под приоритеты BI и под условие «двигаемся без данных BI».

1. **Экспорт IFC→Revit и DWG (C1).** Закрывает единственный явный приоритет
   BI, где у нас прямой ноль, и снимает возражение «PNG/PDF мало». Делается на
   нашей канонической модели без данных BI.
2. **Честная экономика в реал-тайм (B1.2).** Приоритет BI №1: переключатель
   «класс/материал/дизайн-код → дельта стоимости», явная пометка
   placeholder-ставок, готовый разъём под реальную БД себестоимости BI.

Посадку + ТЭП (B2) показываем как **готовое** (демо), а не как задачу в работе.

> Кандидаты «во вторую очередь», если ёмкости хватит: ранжирование 5 вариантов
> (C3) и вынос конструктора секций в UI (C2) — логика под обе уже в коде.

## 5. Запрос Plana → BI

Чтобы соответствовать сборочным регламентам BI и подстроиться под их
квартирографию (озвучено Maxat и Aizat на звонке).

### 5.1 Регламенты и справочники (можно передать без эталонных проектов)

- [ ] Сборочные регламенты BI (как собирается рабочий проект / подшивка Revit).
- [ ] Перечень используемых справочников и баз (классификаторы помещений,
      пирогов полов/стен по типу и классу, ведомости/спецификации).
- [ ] Эталонная квартирография: целевые типы квартир и площади по 3 классам жилья.
- [ ] Стандарт оформления и параметров Revit-моделей (какие параметры
      обязательны, что должно выгружаться в объёмы/смету).

### 5.2 Эталонные документы (после решения юр-статуса / NDA)

- [ ] Утверждённая посадка + квартирография (вход → выход) — чтобы подстроить
      генератор под формат BI.
- [ ] Формат эталонных секций (Revit/DWG) и что именно в них.

### 5.3 Данные для обучения моделей (после NDA)

- [ ] Типовые чертежи / квартирография BI: 3 класса жилья, Revit, 1-й + типовой
      этаж, Астана + Алматы (Алматы — сейсмика/монолит).
- [ ] БД себестоимости элементов и формулы для слоя экономики.

### 5.4 Данные и доступы

- [ ] Какие данные ЕГКН / ГИС-Саулет / Госкадастр уже под договором BI
      (актуальность, периодичность обновления ~раз/мес).
- [ ] Возможность подключить Plana к этим договорным источникам.

## 7. Безопасность и среда (наша готовность)

- Суверенный контур: **Dev (Plana) → Test → Prod (контур BI)**.
- СБ-требование: персональные данные и земельные участки не уходят в global AI.
- Это меняет архитектуру AI-вызовов (сейчас часть генерации идёт во внешние
  модели) — нужно решение по on-prem / суверенным моделям до Prod в контуре BI.
- Решить: тестовая среда — в контуре BI или Plana.

---

## 8. Открытые риски

- **M&A-статус — критический путь.** Пока не ясен — нет данных, ТЗ, бюджета.
- **Скоуп расширяется быстро** (тест-фит + экономика + дизайн-коды + 3D +
  мастер-планы). Фиксируем 2 задачи письменно, иначе фокус расплывётся.
- **СБ vs внешние AI-модели** — генерация во внешние модели несовместима с
  требованием «данные не уходят в global AI» для Prod в контуре BI.
