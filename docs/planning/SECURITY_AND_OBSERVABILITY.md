# Security and Observability

## Цель

Plana обрабатывает проектные файлы, пользовательские данные и платные AI-запросы.
Безопасность и наблюдаемость должны быть частью MVP, а не последним этапом.

## Основные риски

- небезопасный JWT secret или неправильная защита маршрутов;
- доступ пользователя к чужим проектам и файлам;
- вредоносные или слишком большие DXF, DWG, IFC и PDF;
- утечка исходных данных через AI-провайдера;
- неограниченная стоимость AI-запросов;
- долгие запросы, зависшие процессы и заполнение диска;
- потеря проектов при отказе локального хранилища;
- ложное доверие к нормативным и стоимостным результатам.

## Security baseline для MVP

- обязательный секрет без значения по умолчанию;
- единая модель авторизации frontend и backend;
- проверка ownership на каждом project и asset endpoint;
- ограничение типов, размеров и количества загрузок;
- безопасные имена файлов и изоляция хранилища;
- CORS только для разрешённых origins;
- rate limits для auth, AI, import и export;
- журналирование значимых действий;
- отсутствие секретов в репозитории и логах;
- dependency scanning в CI;
- явная политика отправки данных AI-провайдеру.

## Threat modeling checkpoints

Security review обязателен перед:

- production auth;
- публичной загрузкой файлов;
- подключением DWG-конвертера;
- командным доступом к проектам;
- оплатой и биллингом;
- запуском фоновых workers;
- публичным API.

## Sentry и логи

Sentry должен собирать:

- frontend exceptions;
- backend exceptions;
- ошибки API с correlation ID;
- ошибки AI-провайдера;
- ошибки import/export;
- длительность тяжёлых операций;
- release и environment.

Структурированные логи должны содержать:

- request ID;
- user ID без чувствительных данных;
- project ID;
- endpoint или task type;
- duration;
- result status;
- provider/model для AI;
- размер файла для import/export.

## Не логировать

- JWT и API keys;
- пароли;
- полный пользовательский brief без необходимости;
- содержимое загруженных файлов;
- персональные данные;
- подписанные URL.

## Минимальные эксплуатационные метрики

- API error rate;
- p95 latency;
- AI success rate, latency и стоимость;
- import/export success rate;
- размер хранилища;
- количество активных проектов;
- частота ошибок сохранения;
- частота ошибок повторного открытия проекта.

## Production requirements

До production beta нужны:

- PostgreSQL;
- объектное хранилище;
- резервные копии и проверка восстановления;
- очередь задач;
- secrets management;
- HTTPS;
- dependency и container scanning;
- runbook для основных отказов;
- SLO для критического пользовательского сценария.
